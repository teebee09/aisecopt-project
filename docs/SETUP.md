# AISecOpt — Setup and Reproduction Guide

This document allows an examiner to reproduce the system from a clean machine. Every command specifies which terminal it should be run in.

---

## Prerequisites

| Component | Version | Mandatory | Purpose |
|---|---|---|---|
| Python (Anaconda) | 3.11 | Yes | All data processing and model training |
| Docker Desktop | Current | Yes | Hosts Elasticsearch and Kibana |
| Git | Current | Yes | Repository access |
| AWS CLI | v2 | Only for dataset download | Retrieves CSE-CIC-IDS2018 from public S3 |
| Metricbeat | 8.13.0 | Only for live telemetry | Infrastructure metric collection |

**Hardware note.** Development was carried out on a Windows 11 machine with 16 GB RAM. This proved to be a binding constraint: the full dataset could not be loaded into memory in a single pass, which directly shaped the chunked processing approach described in §3. A machine with 32 GB would remove several workarounds but is not required to run the system.

## 1. Python environment

**Anaconda Prompt:**

```bash
conda create -n aisecopt python=3.11
conda activate aisecopt
```

```bash
pip install pandas numpy scikit-learn xgboost imbalanced-learn shap tensorflow matplotlib seaborn jupyter joblib pyarrow fastparquet
```

```bash
pip install "elasticsearch==8.13.0"
```

The Elasticsearch client version is pinned deliberately. The current release defaults to a 9.x client, which sends a version-9 compatibility header that an 8.13.0 server rejects with a 400 error. Client and server versions must match.

**Verify:**

```bash
python -c "import pandas, numpy, sklearn, xgboost, imblearn, shap, tensorflow, joblib, elasticsearch, pyarrow; print('All libraries OK')"
```

## 2. Elastic Stack

**VS Code integrated terminal**, from the project root:

```bash
docker compose up -d
```

Wait for initialisation, then confirm:

```bash
curl http://localhost:9200
```

A JSON response containing `"cluster_name":"docker-cluster"` indicates success. Kibana becomes available at `http://localhost:5601` roughly 30–60 seconds later.

**On Linux hosts only**, Elasticsearch requires a kernel parameter to be raised before first start:

```bash
sudo sysctl -w vm.max_map_count=262144
```

**CORS.** The compose file enables `http.cors` restricted to localhost origins. This is required for the browser-based dashboards to query Elasticsearch directly. Security is disabled (`xpack.security.enabled=false`) — acceptable for a local prototype, and explicitly not a production configuration.

## 3. Dataset acquisition

**VS Code terminal:**

```bash
mkdir -p data/cic2018_raw
aws s3 cp --no-sign-request --region ca-central-1 "s3://cse-cic-ids2018/Processed Traffic Data for ML Algorithms/" ./data/cic2018_raw/ --recursive
```

`--no-sign-request` is used because the bucket is public; no AWS account or credentials are required.

This retrieves ten daily CSV files totalling approximately 6 GB. The raw PCAP captures (~450 GB) are not used — the processed flow records generated by CICFlowMeter-V3 are the appropriate input for flow-level classification.

---

## 4. Running the pipeline

**Anaconda Prompt or VS Code terminal:**

```bash
conda activate aisecopt
jupyter notebook
```

Execute the notebooks in order:

**`01_eda_and_cleaning.ipynb`** — Cleans all ten daily files and produces the stratified sample.

Expected runtime: 15–30 minutes. The cleaning function processes files in 200,000-row chunks and writes each output to a temporary file that is renamed only on successful completion. This design is not incidental: earlier non-chunked versions exhausted available memory partway through the largest file, leaving a partially-written Parquet file that subsequent runs incorrectly treated as complete. The temporary-file pattern makes the "already processed, skip" check trustworthy.

Output: `data/cic2018_clean/cic2018_final_sampled.parquet` — 1,041,092 rows, 15 classes.

**`02_ml_training.ipynb`** — Trains the classifier and populates Elasticsearch.

Expected runtime: 10–15 minutes for training. Requires Elasticsearch to be running for the final ingestion cells.

Outputs: model artefacts in `models/`, figures in `outputs/`, security events in the `ai-secopt-threats-*` indices.

**`02_lstm_forecasting.ipynb`** — Requires collected Metricbeat telemetry (see §5). Trains the forecasting model and writes forecast and actual values to Elasticsearch.

**`03_baseline_comparison.ipynb`** — Reproduces the rule-based baseline comparison. Runs in approximately 3 minutes.

**`04_performance_analysis.ipynb`** — Measures ingestion throughput and resource utilisation.

**Ordering constraint.** The train/test split in notebooks 02 and 03 uses `random_state=42` with stratification, which guarantees an identical partition across runs. This is what makes the baseline comparison valid — both models must be evaluated on precisely the same held-out rows. If the sampled dataset is regenerated, both notebooks must be re-run.

## 5. Infrastructure telemetry (optional)

Required only if collecting fresh telemetry rather than using the supplied trained model.

**Download** Metricbeat 8.13.0 from `https://www.elastic.co/downloads/past-releases/metricbeat-8-13-0` and extract to a path without spaces (e.g. `C:\Elastic\metricbeat-8.13.0`).

Version matching matters here for the same reason as the Python client: a 9.x agent against an 8.13.0 server produces setup failures.

**Administrator PowerShell**, in the extracted directory:

Edit `metricbeat.yml`:

```yaml
output.elasticsearch:
  hosts: ["http://localhost:9200"]

setup.kibana:
  host: "http://localhost:5601"
```

Then:

```powershell
.\metricbeat.exe modules enable system
.\metricbeat.exe test config
.\metricbeat.exe test output
.\install-service-metricbeat.ps1
Start-Service metricbeat
```

Both `test` commands should pass before installing the service. A TLS warning is expected and harmless — the local connection is plain HTTP by design.

**Querying collected data.** Metricbeat 8.x writes to data stream backing indices prefixed `.ds-`. Index patterns must therefore use `*metricbeat*` rather than `metricbeat-*`; a leading-anchored pattern silently returns zero results.

## 6. Dashboards

**VS Code terminal:**

```bash
cd dashboard
python -m http.server 8080
```

Open `http://localhost:8080/index.html`. All six modules share a common navigation bar and a light/dark theme toggle whose preference persists via `localStorage`.

The dashboards must be served over HTTP. Opening the HTML files directly produces a `file://` origin, which browsers block from making cross-origin requests irrespective of server-side CORS configuration.

---

## 7. Kibana index patterns

For the Kibana dashboards, create data views under **Stack Management → Data Views**:

| Pattern | Time field |
|---|---|
| `ai-secopt-threats-*` | `@timestamp` |
| `ai-secopt-forecasts-*` | `@timestamp` |
| `ai-secopt-actuals-*` | `@timestamp` |
| `*metricbeat*` | `@timestamp` |

**Time range.** Kibana defaults to the last 15 minutes. Because the security events and infrastructure telemetry were generated on specific dates, panels will appear empty until the range is widened to cover the relevant period. The two dashboards should have "store time with dashboard" enabled so each retains its own appropriate window.

## 8. Troubleshooting

| Symptom | Cause | Resolution |
|---|---|---|
| `MemoryError` during cleaning | Insufficient free RAM | Restart the Jupyter kernel; stop Docker during cleaning; close other applications |
| Elasticsearch client 400 error | Client/server version mismatch | `pip install "elasticsearch==8.13.0"` |
| Dashboard panels empty | Kibana time range too narrow | Widen to cover the data generation period |
| Dashboard fetch errors in console | Serving from `file://` | Use `python -m http.server` |
| Zero Metricbeat results | Wrong index pattern | Use `*metricbeat*`, not `metricbeat-*` |
| Metricbeat service stuck "StopPending" | Hung process | `Get-Process metricbeat \| Stop-Process -Force`, then restart the service |
| Docker "Engine stopped" (Windows) | WSL2 features not enabled | Enable via DISM: `Microsoft-Windows-Subsystem-Linux` and `VirtualMachinePlatform`, then reboot |
